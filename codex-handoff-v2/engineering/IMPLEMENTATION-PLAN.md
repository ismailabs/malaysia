# Work packages and dependency gates

## WP0 — Freeze and inspect V1
Check source, tags, production readback; collect V1 baseline stills and dynamic scene evidence. Confirm `AGENTS.md` V2 activation and project permissions. No upstream changes yet. Deliver baseline report.

## WP1 — Concepts / 2 prototypes
Timebox concept research, use skills once per meaningful role, source credible map data and a minimum authentic photo asset subset, build A and B minimal functional prototypes. Capture browser media, simulate reduced motion, assess. Choose one, write decision. **Gate:** prototype evidence before broad site rewrites.

## WP2 — Build shared V2 system
Implement distinct brand tokens, global navigation, map layer, motion controller, persistent but nonblocking skip/pause controls, responsive fallback patterns, original design assets and rights ledger. Start with an independently strong first fold.

## WP3 — Hero plus gallery
Develop map→real photographic destination transition. Verify correct geography, no blank intervals, labels and real links. Develop gallery's four changing environmental states; test scrub/pin/no-JS/mobile.

## WP4 — Destination-specific acts
Maintain static routes/content; implement four genuinely distinct hero and local interaction types. Validate that template reuse does not erase differences; keep source `scripts/generate_site.py` synchronized.

## WP5 — Studio finale / growth
Integrate authored conversion scene and verified link to studio. Maintain semantics, internal links, metadata, destination excerpts; click hook stays no-collection unless available consent/access. Accessibility and copyright credits.

## WP6 — Browser refinement
Run local verification, create matched screenshot/motion comparisons, correct actual weaknesses; minimum two substantive fixes rounds. Generate board and visual gate report; fix until **objective** criteria pass and human-readable review supports a substantial qualitative shift. Do not require arbitrary self-given creativity score.

## WP7 — Release
Lock artifact, preserve no-index preview, test preview, deploy production existing Worker/domain, verify hosted pages and new interactions (not just HTTP codes). Confirm old Vercel redirect unchanged. Record version, evidence, Git SHA, rollback and remaining limits. If blocked by auth or runtime limits, complete safe substeps and transparently report.

## Efficiency tips
Batch static content changes, use browser screenshot matrices intelligently, don't rewrite all four pages in separate unsynchronized passes, avoid uncontrolled asset hunting and large dependency installs, do not endlessly refine dead prototype concepts. Actual verification is required, but duplicated tests without code changes or new risks are unnecessary.
